1. What this demo is

Virtual Patient Digital Twin is an offline-first, frontend-only demonstration. Everything runs in your browser using IndexedDB with a localStorage fallback (vpdt: prefix). There is no server, no database upload, no real SMS/call/payment. All patient records in this demo are synthetic (PT-1001 … PT-1010 and any patients you register locally).

2. Data we store locally (and why)

  • Patient onboarding: name, age, gender, blood group (optional), allergies, phone (required), email (required), emergency contact (optional), preferred language, wake phrase. Purpose: to build the synthetic digital twin, show dashboard/medicines/timeline, and enable demo call/mail links. Legal basis / consent: explicit consent screen (Step 2 of 2) before the dashboard continues.
  • Health demo data: diagnoses, labs, medicines, visits, wearable readings (heart rate, HRV, steps, sleep, SpO2, BP, sugar), medicine logs, alerts, advice, follow-ups, ABHA ID demo field. Purpose: trends, explainable rule-based risk scores, doctor triage, caregiver limited view.
  • Staff demo accounts: Staff ID + 4-digit PIN (e.g. DOC-1001 / 1234), optional local WebAuthn passkey. Purpose: demo role-based UI only.
  • Support data: theme, language, consent records, audit log (actor, role, action, patient, message), sync queue (simulated), certificates generated locally.
  • Assistant questions: free-text health questions you type are answered from an on-device knowledge base (or optional local Ollama at localhost:11434 if you run it). Nothing is sent to a vendor cloud by this app.

We do not collect: Aadhaar, full address, financial details, or real medical records. If you type real personal data into demo fields, it stays in this browser — please use synthetic data only.

3. Cookies and trackers

No HTTP cookies. No Google Analytics, Meta Pixel, Hotjar, chat widgets, YouTube, Maps, or external fonts. Storage is IndexedDB + localStorage only.

4. Consent, purpose limitation, minimisation

  • Onboarding consent is granular (data storage required; doctor sharing, caregiver access, microphone, camera, notifications, AI features optional, all unchecked by default).
  • Purpose: demo features only. We do not sell data or use it for advertising (there is no transmission at all).
  • Caregivers see only medicines, appointments, emergency alerts and basic wellness, and only while the patient keeps sharing switched on.
  • Microphone/camera/notifications start only when you activate those features.

5. Your rights (including India DPDP Act)

  • Access / export: Settings → Export Demo Data (JSON) and ABDM-aligned record download.
  • Correct: Settings → My contact (phone/email/emergency), doctor dashboard edit-patient, consent change screen.
  • Erase: Settings → Delete My Data / Reset Demo (removes local store in this browser).
  • Withdraw consent: Settings → View / Change consent, Revoke caregiver access, Disable camera/mic/notifications; footer → Cookie settings. Withdrawing stops future use; already-generated local data is deleted via Delete My Data.
