Consultation-ready features

NEW
📋 Ready-to-Use Patient Story
At the start of every consultation the doctor instantly sees a structured, complete clinical summary — problems, vitals, medicines, adherence, visits, alerts, pending follow-ups and latest instructions — with copy/print support.
🔗 Continuity of Care
Tracks medications, previous instructions and follow-ups with due dates and done-states, shared between the doctor dashboard, patient app and history timeline.
🇮🇳 ABDM-aligned (demo)
ABHA ID demo field plus consent-aware portable JSON export. No real ABDM network call — everything stays in this browser. A real deployment would use ABHA login, Consent Manager and HIP/HIU gateways.

Open the doctor dashboard → select a patient → see “Patient Story”, “Continuity of Care” and “ABDM / ABHA” cards at the top. Patients see “My ongoing care” and “My ABHA / ABDM” cards on their dashboard.

About

        

        
sushruta labs  is an offline-first, frontend-only demonstration that combines synthetic
          EHR data (demographics, diagnoses, labs, medicines, visits, notes, payments) with synthetic
          wearable data (heart rate, HRV, steps, sleep, SpO2, BP, blood sugar, respiratory rate,
          symptoms) to produce an explainable digital representation of a patient.

        
It demonstrates: consent and privacy flows, patient onboarding, wellness scoring, rule-based risk assessment
          with visible reasons, doctor triage and advice approval, nurse escalation, caregiver consent scoping,
          medication logging, voice assistant, audit logging, mock
          payments, teleconsultation, treatment certificates with QR verification, simulated offline sync and PWA
          installation.

        
      


      
      

        

          
Privacy
DESIGN PRINCIPLES
        

        
India-focused data protection discussion points. These are design principles for
            discussion, not legal certification. This demo claims no HIPAA / GDPR / DPDP compliance.

        
    
          
  • Consent — explicit accept/decline before onboarding continues; consent is viewable,
            changeable and revocable in Settings.
    • 
          
  • Purpose limitation — data is used only to drive this demonstration's features.
    • 
          
  • Data minimisation — only synthetic fields are stored; microphone runs on-device
            and only when started by the user.
    • 
          
  • Access control — role-based UI (patient / doctor / nurse / caregiver) with caregiver
            scoping limited to the granted consent items.
    • 
          
  • Auditability — every important action creates an audit event (actor, role, action,
            patient, message).
    • 
          
  • Data deletion — “Delete My Data” removes locally stored demo data after confirmation.
          
    • 
          
  • Data export — “Export Demo Data” downloads a JSON copy of your local synthetic records.
          
    • 
        

        
A real healthcare deployment requires a secure backend, encryption, identity management,
          access control, regulatory compliance, professional security testing and secure infrastructure.

      


      
      

        

          
Limitations

        

        
    
          
  • Wake phrase — the Web Speech API is not equivalent to a dedicated always-on wake-word
            engine.
    • 
          
  • Risk engine — simple deterministic rules, not validated clinical AI; thresholds are
            demonstration values.
    • 
          
  • Wearable data / EHR — synthetic data only.
    • 
          
  • Payments — mock only; no banking or payment systems are connected.
    • 
          
  • SMS / calls — simulated only; nothing is sent to a real phone.
    • 
          
  • Doctor authentication — WebAuthn availability depends on browser, device and security
            context; a demo PIN fallback is provided and status is reported honestly.
    • 
          
  • Ollama — optional and dependent on a local installation and network permissions; the app
            works without it.
    • 
          
  • Offline sync — a simulated local queue without a real backend; nothing is uploaded to a
            hospital server.
    • 
          
  • Medical use — this prototype must not be used to diagnose, treat, or make emergency
            medical decisions.
